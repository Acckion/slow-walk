# ADR-003：风险引擎保持确定性与可解释性

## 状态

已接受。

## 决策

`MedicationRiskEngine` 由一组独立 `MedicationRiskRule` 组成。每条规则接收相同
上下文并返回零个或一个可解释 finding；引擎按照稳定顺序执行规则、保留全部原因，
最终风险取所有命中规则的最高等级。

风险引擎：

- 只依赖 `SlowWalkDomain` 与 Foundation。
- 通过初始化器接收规则、Clock 和配置阈值。
- 相同输入和相同配置必须得到相同业务结果。
- 不访问 UI、网络、数据库、服务端框架或 Apple 平台 API。
- 不调用大语言模型，也不包含随机判断。
- 不将风险简化为单一 Boolean。

## 原因

用药风险提示需要能够回答“哪条规则、基于什么证据、为什么得到这个等级”。外部
生成式模型的输出可能随时间、模型版本或提示变化，无法作为最终等级计算的可靠
依据。确定性规则能够被单元测试、审计和复现，也能在离线环境运行。

## 合并规则

1. `red` 高于 `orange`、`yellow` 与 `green`，低级结果不能覆盖高级结果。
2. 保留所有有效原因，并按照规则标识符的稳定顺序输出。
3. 证据不完整时不能默认绿色。
4. 建议动作去重后保持稳定顺序。
5. `assessedAt` 来自注入的 Clock，不在规则内部散落 `Date()`。

## 医疗边界

规则只能整理来源支持的信息并产生风险提示。演示阈值必须集中配置并明确标记为
非临床标准；任何规则都不能自行推导剂量、诊断或治疗方案。
